# Планировщик жизни — Telegram Mini App

Одно общее пространство на семью: бюджет, каталог продуктов с ценами по магазинам, план питания в трёх вариантах (дёшево / средний / премиум), тренировки с прогрессией и напоминания от бота.

```
данные тела → цели КБЖУ → план питания (3 варианта) → цены по магазинам → список покупок
                                                              |
покупки по категориям  <------  «купили ли то, что планировали?»
        |
        v
бюджет: чистый доход − обязательные − продукты − прочее = остаток
```

## Что внутри (версия 0.1)

| Раздел | Возможности |
|---|---|
| **Главная** | Остаток денег за месяц, цель КБЖУ на сегодня, напоминания с сериями, прогресс закупки по плану |
| **Еда** | Продукты с КБЖУ, цены общие и по магазинам с историей и динамикой, базовый набор из 24 продуктов, генерация планов (линейное программирование HiGHS), сравнение магазинов, общий список покупок с отметками, «план против факта» |
| **Бюджет** | Доходы с налогом (НДФЛ по прогрессивной шкале, фиксированная ставка, НПД), обязательные расходы (месяц/квартал/год), покупки по категориям с позициями, счётчик расходов на питомцев, показ в ₽ и $ |
| **Развитие** | 5 стартовых программ, библиотека упражнений, конструктор программ, запись подходов, двойная прогрессия, чтение и свои цели |
| **Напоминания** | Сообщения от бота с кнопками «Готово / Через 15 мин / Пропустить», серии, тренировки по программе, питомцы, платежи |
| **Ещё** | Люди, дети, питомцы; приглашения с ролями «редактор» и «наблюдатель»; несколько пространств; налоги, категории, магазины, доли приёмов пищи; экспорт в JSON |

## Архитектура

```
Telegram ──открывает Mini App──> Render: Fastify (Node.js, TypeScript)
                                  ├─ /        статика public/ (HTML, CSS, JS-модули, без сборки)
                                  └─ /api/*   проверка initData (HMAC), роли, данные
                                         │
                                         v
                                  Supabase
                                  ├─ Postgres (RLS включён без политик; доступ только у сервера и функций)
                                  ├─ Edge Function reminders     ← Supabase Cron раз в минуту, шлёт напоминания
                                  └─ Edge Function telegram-bot  ← вебхук: кнопки «Готово / Отложить / Пропустить», /start
```

- Личность пользователя — только из подписанного `initData` Telegram (HMAC-SHA256 на ключе из токена бота, срок 24 ч).
- Браузер никогда не обращается к Supabase. Сервер использует секретный ключ и сам проверяет членство и роль в пространстве на каждом запросе.
- Напоминания целиком в Supabase: сервер на Render для них не нужен, поэтому его засыпание на бесплатном плане им не мешает.
- Все суммы хранятся в копейках (целые числа).

```
src/
  server.ts          Fastify, статика, подключение маршрутов
  auth.ts            проверка подписи initData
  access.ts          роли: owner / editor / viewer
  bot.ts             имя бота (getMe) и отправка файлов
  routes/            spaces, people, budget, food, training, reminders
  lib/               mealEngine (HiGHS), targets (Миффлин — Сан-Жеор), tax, progression, streak
  scripts/           seed-exercises
  tests/             модульные тесты логики
public/              фронтенд без фреймворка и сборки
supabase/
  001_schema.sql, 002_seed_training.sql
  functions/         Edge Functions: reminders, telegram-bot
  config.toml        настройки функций
```

## Запуск

### 1. Бот

В [@BotFather](https://t.me/BotFather) создайте бота (`/newbot`) и сохраните токен.

### 2. Supabase: база

1. **SQL Editor** — выполните по очереди `supabase/001_schema.sql` и `supabase/002_seed_training.sql` (второй можно запускать повторно).
2. **Project Settings → API** — скопируйте **секретный** ключ (`sb_secret_…`). Публикуемый `sb_publishable_…` серверу не подходит.

### 3. Render: приложение

**New → Blueprint** → этот репозиторий. Заполните три переменные:

| Переменная | Значение |
|---|---|
| `SUPABASE_URL` | уже указан |
| `SUPABASE_SECRET_KEY` | секретный ключ Supabase |
| `BOT_TOKEN` | токен бота |

Имя бота сервер узнаёт у Telegram сам. После деплоя в @BotFather: `/mybots → бот → Bot Settings → Configure Mini App` — укажите адрес сервиса (так работают ссылки-приглашения `t.me/<бот>?startapp=…`).

### 4. Supabase: бот и напоминания

```powershell
npx supabase login
npx supabase link --project-ref muzkjlwstmeodcoxtqlx
npx supabase secrets set BOT_TOKEN=<токен> APP_URL=https://<сервис>.onrender.com
npx supabase functions deploy reminders
npx supabase functions deploy telegram-bot
```

1. Откройте один раз в браузере `https://muzkjlwstmeodcoxtqlx.supabase.co/functions/v1/telegram-bot?setup` — функция зарегистрирует себя вебхуком бота и поставит кнопку меню.
2. **Integrations → Cron → Create job**: тип **Supabase Edge Function**, функция `reminders`, расписание `* * * * *` (каждую минуту).

### 5. Библиотека упражнений (необязательно)

Встроенные 31 упражнение уже есть. Расширенная библиотека — из [Free Exercise DB](https://github.com/yuhonas/free-exercise-db) (общественное достояние, Unlicense): уровни «начальный» и «средний», инвентарь — своё тело, гантели, резинки, гири.

```powershell
npm run seed:exercises
```

С флагом `-- --images` картинки копируются в Supabase Storage (бакет `exercises`) вместо ссылок на GitHub. Русские названия для записей набора добавляются в `seed/exercise-names-ru.json` (`"id записи": "Название"`); без перевода показывается английское имя.

## Локальная разработка

```powershell
npm install
Copy-Item .env.example .env   # впишите SUPABASE_SECRET_KEY и BOT_TOKEN
npm run dev
```

Вне Telegram приложение открывается в обычном браузере в режиме разработки: при `DEV_AUTH=1` откройте `http://localhost:3000/?dev=12345` (число — условный Telegram ID). В продакшене (`NODE_ENV=production`) этот режим отключён.

```powershell
npm test
```

Тесты проверяют подпись initData, расчёт КБЖУ, НДФЛ, прогрессию, серии и движок питания (все три варианта, недостижимые цели).

## Как работает подбор плана

Для каждого человека решается задача линейного программирования (HiGHS): переменные — граммы продукта в каждом приёме пищи.

- Калории в пределах ±3% от цели, белок не ниже цели, жиры и углеводы ±15%.
- Калории каждого приёма — ±10% от его доли (доли настраиваются в «Ещё → Приёмы пищи»).
- Продукт попадает только в подходящие приёмы (завтрак / основной / перекус) и в рамках мин./макс. граммов в день.
- **Дёшево** — минимальная стоимость. **Средний** — не меньше 8 продуктов от 30 г, без продукта больше 60% от максимума, штраф за перекос. **Премиум** — максимум «качественных» калорий, бюджет не выше ×2,2 от дешёвого, не меньше 12 продуктов.
- Если задача неразрешима, ограничения ослабляются по шагам (жиры и углеводы до ±25%, белок до 90%), а если и это не помогает — приложение говорит, что именно мешает. Неправильные цифры молча не возвращаются.

Цена продукта для магазина: цена этого магазина → общая цена → продукт исключается с предупреждением. При выборе «Любой» берётся общая цена, а если её нет — самая низкая из магазинов.

## Важно

- Шкала НДФЛ по умолчанию: 13% до 2,4 млн ₽ в год, 15% до 5 млн, 18% до 20 млн, 20% до 50 млн, 22% свыше. Это данные, а не код — проверьте по действующему законодательству и при необходимости измените в «Ещё → Налоги». Месячный налог — среднегодовой.
- Для детей формулы взрослых не используются: калорийность задаёт родитель, БЖУ 15/30/55%.
- Программы тренировок — общие рекомендации для поддержания формы, не медицинский совет.
